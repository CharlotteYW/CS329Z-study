# CS329Z Learning Roadmap

**Starting point:** 10 years of backend engineering and a mini Claude Code-style agent already built. **Budget:** 3–4 hours per week. Use that experience to discuss design decisions at depth. Review introductory concepts when a lecture, note, or assignment exposes a specific question.

Start with [Week 1](lectures/week-01-plan.md). The default cycle is **watch → write a short note → read one relevant paper or article → discuss → apply in homework or the project**. Before viewing, the mentor points out a question to listen for. Afterward, the mentor reviews the note, asks one follow-up, and recommends the next resource or task. During assignments, the mentor gives hints and reviews decisions and tests while the learner does the work.

On a typical lecture week, set aside roughly **90–120 minutes for lectures and notes, 30–45 minutes for selected reading and comparison, and 60–75 minutes for discussion or applied work**. Shift more of the weekly budget to implementation and evaluation during homework and project weeks. Stretch topics or assignments across weeks as needed. Use the week's `references.md` for the exact reading sections and comparison task.

## Course sequence and applied work

The table preserves the [official Fall 2026 lecture order](resources/course-materials.md). Start with the video for each session, or slides and a relevant reading when it is unavailable. The last two columns suggest where to focus and what a note, discussion, assignment, or project could demonstrate. They do not add separate projects or a mandatory reading list.

| Course module and lectures | Engineering decision and useful source | Evidence to move on |
|---|---|---|
| M1 Foundations — [L01](resources/course-materials.md#l01) | Where should control live? Use L01's workflow/agent comparison and the introduction to *AI Agents That Matter*. | Use one example to explain when adaptive control earns its extra cost and what evidence would change the decision. |
| M2 Models and retrieval — [L02](resources/course-materials.md#l02), [L03](resources/course-materials.md#l03) | What belongs in context, retrieval, or structured output? Start with *Effective Context Engineering*; consult the RAG, DPR, or ColBERT papers as needed for lexical, dense, hybrid, or reranked retrieval. | On identical queries, separate retrieval misses from unsupported answers. Report recall, grounding, and latency or context cost for one comparison. |
| M3 Tools and orchestration — [L04](resources/course-materials.md#l04), [L05](resources/course-materials.md#l05) | Which execution, validation, retry, and state guarantees belong in the harness? Use the course's MCP revision and L05 demos to compare the existing loop with LangGraph and DSPy. | Explain how the current loop handles timeout, malformed action, and restart, with evidence where relevant. Show what a framework would add or change. |
| M4 Patterns and memory — [L06](resources/course-materials.md#l06), [L07](resources/course-materials.md#l07) | When does a ReAct-style loop beat a fixed workflow? Which working, episodic, semantic, or procedural state should survive context compaction? Start with ReAct or MemGPT, depending on the question. | Compare two context or state policies on the same task. Investigate one quality, stale-state, or isolation failure. |
| M5 Multi-agent systems and optimization — [L08](resources/course-materials.md#l08), [L09](resources/course-materials.md#l09) | Does delegation improve outcomes under the same budget? Consult the multi-agent failure taxonomy; use GEPA or MIPRO for context optimization. Compare prompt/context changes with weight updates conceptually. | Use a matched single-agent baseline and held-out tasks. Attribute any gain or regression to a change, accounting for coordination, calls, and latency. |
| M6 Data — [L10](resources/course-materials.md#l10), [L11](resources/course-materials.md#l11), [L12](resources/course-materials.md#l12) | Which traces, demos, human feedback, or synthetic examples are useful for improving and measuring the system? Start with Terminal-Bench and *Data Flywheels*; use the validation papers when deciding how to curate data. | Version a small trace dataset with provenance, labels, limitations, and a split that avoids task-family leakage. Explain one coverage gap. |
| M7 Evaluation — [L13](resources/course-materials.md#l13) | Does the benchmark measure the user's goal? Use the course's benchmark design paper and its request, environment, stopping criteria, and scorer framework. | Reproduce an evaluation with a baseline, independent correctness check, versioned configuration, repeat policy, and error breakdown. |
| M8 Judges and evaluation infrastructure — [L14](resources/course-materials.md#l14), [L15](resources/course-materials.md#l15), [L16](resources/course-materials.md#l16) | Where do deterministic grading, human review, and model judges each add value? Use *Demystifying Evals for AI Agents*, the MT-Bench judge study, and the SWE-bench guest materials or paper. | Audit one scorer against labeled outcomes, discuss bias and disagreement, and explain how repeated trials change the interpretation of pass@k versus pass^k. |
| M9 Safety and reliability — [L17](resources/course-materials.md#l17) | Where should permissions, data boundaries, and approvals be enforced? Use the lecture or PrivacyLens, with other listed privacy readings as needed. | Show a local regression test for a trust or permission boundary and a benign case that still succeeds. Describe remaining risks. |
| M10 Coding and personal agents — [L18](resources/course-materials.md#l18), [L19](resources/course-materials.md#l19) | Which interface helps a coding agent make correct changes? When should a proactive system act, ask, or wait? Use SWE-agent's interface ablations and the GUM paper. | Compare interface behavior on repeatable coding tasks; justify when to defer an action. For the project, reproduce an evaluation and defend results and limitations. |

## Milestones

- **HW1:** Review the current handout around M3 and plan required harness work through M6. Reuse prior understanding to move faster, while following the official framework and submission rules. See [assignment guidance](assignments/README.md).
- **HW2:** Orient during M6 and build evidence through M7–M8. Prior practice can prepare the work; the official specification sets the deliverables.
- **Project:** Choose a direction after comparing candidates around M2–M3. The existing agent is an option, and the learner decides. Define a baseline and success criteria before expanding scope. See [project milestones](project/README.md).
- **Paper presentation:** Shortlist after M4 and rehearse around M8 using the [paper-reading guide](readings/README.md). An inaccessible course event uses the documented reading or self-study substitute in the resource index.

Check understanding with a single follow-up tied to the notes. At major milestones, use the [review rubric](reviews/README.md), including application to a new case. Record evidence and the next step in [progress](PROGRESS.md). Formal homework and project completion follow their own requirements.
